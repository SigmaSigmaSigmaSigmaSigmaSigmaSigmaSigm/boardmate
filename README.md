# BoardMate — компанія для настільних ігор

BoardMate допоможе знайти людей, з якими можна пограти в настільні ігри у своєму місті. Користувач обирає гру та готову зустріч або створює власну: вказує місце, час і кількість учасників. Інші люди записуються, поки є вільні місця.

Це опис майбутнього застосунку для першої домашньої роботи. API та база даних ще не реалізовані.

## Що буде на сайті

- **Зустрічі.** Пошук за назвою зустрічі або гри, фільтри за містом, грою, місцем і датою. Можна залишити тільки зустрічі з вільними місцями та сортувати за часом або кількістю вільних місць.
- **Сторінка зустрічі.** Опис, гра, адреса, час, організатор, учасники та кнопка запису. До початку можна відмовитися від участі.
- **Каталог ігор.** Пошук за назвою, фільтри за категорією та кількістю гравців, сортування за назвою або тривалістю. На сторінці гри є опис і список зустрічей з нею.
- **Місця для гри.** Список клубів і кафе з адресами. На сторінці місця можна переглянути заплановані там зустрічі.
- **Реєстрація, вхід і профіль.** Користувач може змінити своє ім’я та місто, переглянути власні зустрічі й історію участі.
- **Керування даними.** Організатор редагує та скасовує власні зустрічі. Адміністратор додає, редагує та видаляє ігри, категорії й місця.
- **Про сайт.** Короткий опис, контактна пошта та правила участі.

У першій версії всі зустрічі безкоштовні. Чату, оплати та бронювання столиків у закладах не буде. Організатор сам домовляється із закладом і приносить гру.

### Правила зустрічей

1. На зустрічі грають в одну гру. Місто визначається за місцем проведення.
2. Організатор автоматично стає учасником і займає одне місце. Одна людина може записатися на зустріч лише один раз.
3. Кількість місць має бути між мінімальною та максимальною кількістю гравців для обраної гри. Якщо до початку учасників замало, організатор сам вирішує, чи скасувати зустріч.
4. Записатися або вийти можна лише до початку нескасованої зустрічі. Організатор не може вийти зі своєї зустрічі: він може її скасувати.
5. Якщо місць немає, запис відхиляється. Навіть два одночасні запити не повинні зайняти одне останнє місце.
6. До початку організатор може змінити назву, опис, час і кількість місць. Гра та місце після створення не змінюються. Кількість місць не можна зменшити нижче кількості вже записаних людей.
7. Скасована зустріч залишається в історії, повторно відкрити її не можна. Видалити майбутню зустріч можна, лише якщо ніхто, крім організатора, ще не записаний. Минулі зустрічі не редагуються і не видаляються.

## REST API

### Загальні домовленості

- Усі адреси починаються з `/api/`. У таблицях нижче цей префікс пропущений: `/games/` означає `/api/games/`.
- Тіла запитів і відповідей мають формат JSON: `Content-Type: application/json`. Для `GET` і `DELETE` тіло не передається; відповідь `204 No Content` теж не має тіла.
- `{id}` — додатний цілий ідентифікатор ресурсу в адресі. Параметри пошуку й фільтрів передаються в URL після `?`.
- `POST` створює ресурс. `PATCH` змінює тільки передані поля. Порожній `PATCH`, невідомі поля та спроба записати поле тільки для читання повертають `400`.
- Дата й час передаються з часовим поясом, наприклад `2026-11-14T16:00:00Z`. У відповідях час завжди в UTC (`Z`), на сторінці він відображається в місцевому часі користувача.
- `id`, організатора, час запису, кількість учасників і вільних місць визначає сервер. Клієнт не може обирати іншого користувача для запису.
- В усіх прикладах нижче дані вигадані.

**Доступ:** «усі» — також без входу; «користувач» — після входу; «організатор» — користувач, який створив цю зустріч; «адмін» — адміністратор сайту. Користувач бачить і змінює тільки власний профіль. Паролі ніколи не повертаються у відповідях, пошта доступна лише у власному профілі.

### Списки та помилки

Усі списки приймають `page` — ціле число від `1`, типово `1`. На сторінці до 20 записів. `count` — загальна кількість результатів після фільтрації. `results` містить об’єкти, вказані в таблиці ендпоінтів. Наприклад, список `Category`:

```json
{"count": 1, "page": 1, "results": [{"id": 1, "name": "Стратегії"}]}
```

Для «списку `Game`» у `results` будуть об’єкти `Game`, і так само для інших ресурсів. Порожня або завелика сторінка повертає `200` з `results: []`; `count` зберігає загальну кількість знайдених записів. Для однакових значень сортування додатково використовується `id` за зростанням. Невідомі параметри, неправильні типи та недозволене сортування повертають `400`.

Помилки мають спільний формат:

```json
{"detail": "На цю зустріч більше немає вільних місць."}
```

Ці статуси застосовуються до всіх відповідних ендпоінтів, додатково до успішних відповідей у таблицях:

| Статус | Коли повертається |
| --- | --- |
| `400 Bad Request` | Некоректний JSON, параметр або значення поля; обов’язкове поле пропущено; вказаний у тілі пов’язаний ресурс не існує. |
| `401 Unauthorized` | Для захищеного ендпоінту користувач не увійшов або дані для входу неправильні. |
| `403 Forbidden` | Користувач увійшов, але не має потрібних прав, наприклад редагує чужу зустріч. |
| `404 Not Found` | Ресурсу з ідентифікатором у URL немає. |
| `409 Conflict` | Дія суперечить поточному стану: немає місць, уже є запис, зустріч почалася чи скасована, ресурс використовується. Окремі випадки уточнено нижче. |

### Формати відповідей

Назви `Game`, `Meeting` тощо в таблицях посилаються на JSON-приклади цього розділу. Для `POST` повертається створений об’єкт, для `PATCH` — повний об’єкт з оновленими значеннями.

**Category — категорія гри:**

```json
{"id": 1, "name": "Стратегії"}
```

**Game — настільна гра:**

```json
{
  "id": 3,
  "name": "Лісові стежки",
  "description": "Гравці прокладають маршрути через ліс і збирають очки.",
  "category_id": 1,
  "min_players": 2,
  "max_players": 4,
  "duration_minutes": 45
}
```

**Venue — місце проведення:**

```json
{
  "id": 2,
  "name": "Клуб Гральня",
  "city": "Київ",
  "address": "вул. Прикладна, 10",
  "description": "Місце для зустрічей любителів настільних ігор."
}
```

**Meeting — зустріч:**

```json
{
  "id": 7,
  "title": "Граємо в Лісові стежки",
  "description": "Новачки теж можуть долучитися, правила поясню на місці.",
  "game_id": 3,
  "venue_id": 2,
  "host": {"id": 5, "username": "oleksii", "display_name": "Олексій"},
  "starts_at": "2026-11-14T16:00:00Z",
  "capacity": 4,
  "is_cancelled": false,
  "status": "upcoming",
  "participants_count": 1,
  "available_seats": 3
}
```

`participants_count` враховує організатора, `available_seats = capacity - participants_count`. `status` обчислюється: `cancelled`, якщо зустріч скасована; інакше `past`, якщо час початку вже настав, або `upcoming`. Для `past` і `cancelled` запис закритий незалежно від вільних місць.

**Participant — запис про участь:**

```json
{
  "id": 12,
  "meeting_id": 7,
  "user": {"id": 8, "username": "marta", "display_name": "Марта"},
  "joined_at": "2026-11-10T12:00:00Z"
}
```

Публічно показуються лише `id`, нік та ім’я користувача. Після запису Марти кількість учасників зустрічі стане `2`, а вільних місць — `2`.

**Profile — власний профіль:**

```json
{
  "id": 8,
  "username": "marta",
  "email": "marta@example.com",
  "display_name": "Марта",
  "city": "Київ",
  "is_admin": false
}
```

### Ігри

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `GET /games/` | Каталог / усі | `search`, `category_id`, `players`, `ordering`, `page` | `200`, список `Game` |
| `GET /games/{id}/` | Сторінка гри / усі | `id` у URL | `200`, `Game` |
| `POST /games/` | Додати гру / адмін | JSON з прикладу нижче | `201`, `Game` |
| `PATCH /games/{id}/` | Змінити гру / адмін | `id`; будь-які поля з прикладу | `200`, `Game` |
| `DELETE /games/{id}/` | Видалити гру / адмін | `id` | `204`, без тіла |

`search` шукає частину назви без урахування регістру. `category_id` — ID категорії. `players` — додатне ціле число: повертаються ігри, для яких `min_players ≤ players ≤ max_players`. `ordering`: `name` (типово), `duration_minutes`, `-duration_minutes`.

Тіло створення гри; всі поля обов’язкові:

```json
{
  "name": "Лісові стежки",
  "description": "Гравці прокладають маршрути через ліс і збирають очки.",
  "category_id": 1,
  "min_players": 2,
  "max_players": 4,
  "duration_minutes": 45
}
```

Межі гравців і тривалість — додатні цілі числа, `min_players ≤ max_players`. Якщо гра вже використовується у зустрічах, її видалення повертає `409`. Зміна меж гравців також повертає `409`, якщо кількість місць хоча б однієї наявної зустрічі вийде за нові межі.

Зустрічі на сторінці гри завантажуються через `GET /meetings/?game_id=3`.

### Категорії

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `GET /categories/` | Категорії для фільтра та форми гри / усі | `page`; сортування за назвою | `200`, список `Category` |
| `POST /categories/` | Додати категорію / адмін | `{"name": "Стратегії"}` | `201`, `Category` |
| `PATCH /categories/{id}/` | Перейменувати / адмін | `id`; `{"name": "Сімейні ігри"}` | `200`, `Category` |
| `DELETE /categories/{id}/` | Видалити / адмін | `id` | `204`, без тіла |

Назва обов’язкова та унікальна. Повторна назва — `409`. Категорію, до якої належать ігри, видалити не можна (`409`).

### Місця

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `GET /venues/` | Список місць / усі | `search` за назвою, `city`, `page`; сортування за назвою | `200`, список `Venue` |

| `DELETE /venues/{id}/` | Видалити місце / адмін | `id` | `204`, без тіла |

`search` — частина назви, `city` — повна назва міста; обидва без урахування регістру.

Тіло створення місця; всі поля обов’язкові:

```json
{
  "name": "Клуб Гральня",
  "city": "Київ",
  "address": "вул. Прикладна, 10",
  "description": "Місце для зустрічей любителів настільних ігор."
}
```

Якщо місце використовується у зустрічах, видалення повертає `409`. Зустрічі на його сторінці завантажуються через `GET /meetings/?venue_id=2`.

### Зустрічі

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `GET /meetings/` | Пошук зустрічей / усі | Фільтри з таблиці нижче | `200`, список `Meeting` |
| `GET /meetings/{id}/` | Сторінка зустрічі / усі | `id` | `200`, `Meeting` |
| `POST /meetings/` | Створити зустріч / користувач | JSON з прикладу нижче | `201`, `Meeting` |
| `PATCH /meetings/{id}/` | Редагувати або скасувати / організатор | `id`; `title`, `description`, `starts_at`, `capacity` або `is_cancelled: true` | `200`, `Meeting` |
| `DELETE /meetings/{id}/` | Видалити зустріч без інших учасників / організатор | `id` | `204`, без тіла |

Параметри `GET /meetings/` необов’язкові, усі передані умови застосовуються разом:

| Параметр | Значення |
| --- | --- |
| `search` | Частина назви зустрічі або гри, без урахування регістру. |
| `city` | Повна назва міста місця проведення, без урахування регістру. |
| `game_id` | ID гри. |
| `venue_id` | ID місця. |
| `date` | Дата початку у форматі `YYYY-MM-DD`, за UTC. |
| `has_places` | `true` — тільки майбутні нескасовані зустрічі з вільними місцями; `false` — без цієї додаткової умови. |
| `status` | `upcoming` (типово), `past`, `cancelled` або `all`. |
| `ordering` | `starts_at` (типово, найближчі спочатку), `-starts_at` або `-available_seats`. |
| `page` | Номер сторінки, типово `1`. |

Приклад: `GET /api/meetings/?city=Київ&game_id=3&has_places=true&ordering=starts_at`.

Тіло створення зустрічі; всі поля обов’язкові:

```json
{
  "title": "Граємо в Лісові стежки",
  "description": "Новачки теж можуть долучитися, правила поясню на місці.",
  "game_id": 3,
  "venue_id": 2,
  "starts_at": "2026-11-14T16:00:00Z",
  "capacity": 4
}
```

Час початку має бути в майбутньому, `capacity` — ціле число в межах кількості гравців обраної гри. Порушення цих правил — `400`. Організатор і його запис про участь створюються разом зі зустріччю. `is_cancelled` спочатку `false`.

Приклад редагування: `{"capacity": 3}`. Для скасування передається лише `{"is_cancelled": true}`. Повторне скасування майбутньої вже скасованої зустрічі повертає `200` без змін. Редагування інших полів скасованої зустрічі, будь-яке редагування після часу початку або зменшення кількості місць нижче кількості учасників — `409`.

Видалення після часу початку або за наявності інших учасників повертає `409`. При дозволеному видаленні також видаляється запис про участь організатора. Для збереження зустрічі в історії використовується скасування.

### Участь у зустрічах

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `GET /meetings/{id}/participants/` | Перелік учасників, включно з організатором / усі | ID зустрічі, `page`; порядок за `joined_at` | `200`, список `Participant` |
| `POST /meetings/{id}/participants/` | Записатися самому / користувач | ID зустрічі; без тіла | `201`, `Participant` |
| `DELETE /meetings/{id}/participants/me/` | Відмовитися від власної участі / користувач | ID зустрічі; без тіла | `204`, без тіла |
| `GET /me/meetings/` | Власні зустрічі та історія участі / користувач | `status`: `all` (типово), `upcoming`, `past`, `cancelled`; `page` | `200`, список `Meeting`, за `starts_at` від новіших до старіших |

Для запису `409` означає: користувач уже є учасником, вільних місць немає, зустріч почалася або скасована. Для виходу `409` означає: користувач є організатором, зустріч почалася або скасована. Якщо власного запису немає — `404`.

Вихід видаляє запис про участь і звільняє місце; до початку можна записатися знову. `/me/meetings/` містить зустрічі, у яких зберігся запис користувача, включно зі створеними ним. Зустрічі, з яких користувач вийшов, у його історії не показуються.

### Реєстрація, вхід і профіль

| Метод і шлях | Використання / доступ | Параметри або тіло | Успішна відповідь |
| --- | --- | --- | --- |
| `POST /users/` | Зареєструватися / усі | JSON з прикладу нижче | `201`, `Profile`; після цього потрібен окремий вхід |
| `POST /session/` | Увійти / усі | `{"username": "marta", "password": "example-pass-123"}` | `200`, `Profile`; сервер запам’ятовує вхід |
| `DELETE /session/` | Вийти / користувач | Без тіла | `204`, без тіла; вхід більше не діє |
| `GET /me/` | Переглянути власний профіль / користувач | Без параметрів | `200`, `Profile` |
| `PATCH /me/` | Змінити ім’я та місто / користувач | `display_name` та/або `city`, наприклад `{"city": "Львів"}` | `200`, `Profile` |

Тіло реєстрації; всі поля обов’язкові:

```json
{
  "username": "marta",
  "email": "marta@example.com",
  "password": "example-pass-123",
  "display_name": "Марта",
  "city": "Київ"
}
```

Нік і пошта мають бути унікальними; повторне значення повертає `409`. Нік містить 3–30 малих латинських літер, цифр або `_`. Пошта перед збереженням переводиться в нижній регістр. Пароль має щонайменше 8 символів. Неправильний формат — `400`, неправильний нік або пароль при вході — `401` з однаковим повідомленням «Неправильний нік або пароль».

Під час реєстрації `is_admin` завжди `false`. Зміна ніку, пошти, пароля та прав через `/me/` не передбачена. У публічних списках учасників і в полі `host` профіль повертається без пошти й адміністративних прав.

## Схема бази даних

![Схема бази даних BoardMate: користувачі, категорії, ігри, місця, зустрічі та участь](docs/database-schema.png)

[Відкрити схему у повному розмірі](docs/database-schema.png)

`PK` — унікальний ідентифікатор рядка. `FK` — посилання на рядок іншої таблиці. `1 → N` означає, що одному запису можуть відповідати багато записів в іншій таблиці.

| Таблиця | Для чого потрібна |
| --- | --- |
| `users` | Облікові записи, дані профілю та ознака адміністратора. |
| `categories` | Категорії настільних ігор. Кожна гра має одну категорію. |
| `games` | Опис гри, кількість гравців і тривалість партії. |
| `venues` | Назва, місто, адреса та опис місця. |
| `meetings` | Гра, місце, організатор, час, кількість місць і ознака скасування. |
| `participants` | Зв’язок між користувачем і зустріччю та час запису. |

Усі поля обов’язкові. Текстові поля не можуть бути порожніми або містити тільки пробіли. `id` створюється автоматично. `is_admin` та `is_cancelled` типово `false`, `joined_at` — час створення запису. Обмеження довжини: нік — 30 символів, пошта — 254, ім’я користувача, місто й категорія — 80, назва гри, місця та зустрічі — 120, адреса — 200, опис — 2000. Помилки довжини повертають `400`.

- `username`, `email` та назва категорії унікальні. Повтор категорії перевіряється за точним збігом назви після прибирання пробілів на краях.
- Пара `participants(user_id, meeting_id)` унікальна. Організатор також має один запис у `participants`.
- `min_players > 0`, `max_players ≥ min_players`, `duration_minutes > 0`, `capacity > 0`. Перевірки місць і часу описані в правилах зустрічей.
- `password_hash` зберігає результат захищеного перетворення пароля, а не сам пароль. Для цього буде використаний стандартний механізм Django.
- Категорію з іграми, гру чи місце зі зустрічами та користувача зі зустрічами або участю не можна видаляти зі збереженням неповних зв’язків. Видалення облікового запису через API поки не передбачене.
- При дозволеному видаленні зустрічі видаляються її записи `participants`. Скасування нічого не видаляє.
- `participants_count`, `available_seats` та `status` обчислюються, тому окремих колонок для них немає. Вкладені `host` і `user` беруться з `users`.
- Дані сторінки «Про сайт» можна зберігати в коді: окрема таблиця для одного незмінного опису не потрібна. Службові таблиці механізму входу буде визначено разом з авторизацією.
